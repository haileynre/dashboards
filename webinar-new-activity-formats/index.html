Redesigned Standardization

Adopted 2026-10-08 · applies to every brand from now on

Why we're standardizing

We're moving every brand to one naming and date format for webinar activity in Close so we can track webinar performance reliably and make better decisions with our data. Today the same kind of event is labeled many different ways — a like-live alone appears as Like Live, Subto Like Live, Gator Like Live - May 15th, 2026 and LIKE LIVE - May 14 2026; an AMA as AMA 09/23, October 08 2026 ZDB AMA Registrant or AMA - Date of webinar - October 06 2026. Dates appear in seven formats, and tens of thousands of records lost their date entirely. That turns every cross-brand report into manual cleanup.

Better tracking

One filter finds every webinar of a type in every brand — no list of spelling variations to maintain.

Comparable data

Registrations, attendance and sales per webinar line up across Subto, Gator, TC, ZDB and Deal Scout.

Faster reporting

Smart views, dashboards and automations are built once and reused, instead of rebuilt per brand.

Problems surface early

A missing or malformed date stands out immediately instead of hiding among format variations.

The goal is better business performance: knowing which webinars actually produce leads and sales lets us invest in the ones that work and fix or retire the ones that don't.

Why this matters

01. New Activity is a live edge: 38 zaps write it and one thing listens. There is no shared “webinar date” field, so the date of the event lives inside free text, and every brand formats it differently.

Gator's Goal looks people up by the Funnel + Notes pair (Gator team, 2026-09-02), so the text format is the contract. A “cleaned-up” string silently breaks lookups.

The webinar types

Like-live

A pre-recorded WebinarJam / EverWebinar run presented as live.

True live

Gator's term for its live Saturday Zoom webinar (“NEW NRE SAT – TRUE LIVE”).

Live

A live Zoom webinar under the brand's main funnel (Subto “Live Webinar”, ZDB “Business Acquisition Training”). Gator's true live is its version of this.

AMA / Fireside Chat

The DOE Fireside Chat / AMA series. Both labels appear in the data; “Fireside Chat” values run through spring 2026 and “AMA” values begin May–June 2026. They are treated as separate event types going forward.

How to read it
  • Like-live is the most consistent type. Gator, TC and ZDB all write Like Live {MM/DD/YYYY}. Subto alone adds the word “Registration”.
  • AMAs never set the funnel field in any brand. The type and date live only in the notes field, so a filter on the funnel field will miss every AMA.
  • The funnel field doesn't tell types apart in Gator or TC. Gator true lives and like-lives both use Gator Webinar; TC like-lives use the generic Webinar Funnel. Only the notes field separates them.
  • No TC “live” pattern exists. TC's webinar activities are like-lives and AMAs; the only other TC webinar note is Webinar Hot App (17 records).

SOP — writing a webinar “01. New Activity”

  1. Copy the brand's current pattern exactly from the quick reference, including capitalization, spacing, the hyphen and the brand's date format. Don't normalize across brands; Gator's Goal and any smart view filtering on these strings depend on the exact text.
  2. Build the date from the event, not the run time. The date token is the webinar date. Format it in America/Phoenix, the timezone the Zapier formatters used.
  3. Never ship a blank or literal date token. Test with a real registrant and confirm the date is in the text: no Date of webinar - with nothing after it, and no MMM DD, YYYY left over.
  4. Fill the date field the brand expects. Subto and Gator: Activity Date = today. ZDB: leave it empty (it has never been written for webinars). TC like-lives: the date goes in Notes., not TTTC Webinar Date.
  5. AMAs leave the funnel field empty. If you change that, tell whoever reports on AMAs: today they can only be found by text-searching the notes field.
  6. Write to this brand's field ID. IDs differ per org; use the internal field-ID table.
  7. Verify after the first live run. Group that brand's custom activities by the notes field (method below) and confirm the new value appears with the expected count.
Changing any of these patterns is a contract change — raise it as a Decision first, per the migration rules.

How to re-pull this data

The Close MCP aggregation tool can group custom activities by a text field's exact values. Run it once per brand org:

  • include_types: ["custom_activity"]
  • group_by: [<funnel field id>, <notes field id>]
  • aggregations: [{"aggregation_type": "count"}]

Group by the notes field alone as well. Records with an empty funnel field (every AMA) drop out of a two-field grouping. Adding custom_activity_type_id as a group confirms which activity type a value came from.
